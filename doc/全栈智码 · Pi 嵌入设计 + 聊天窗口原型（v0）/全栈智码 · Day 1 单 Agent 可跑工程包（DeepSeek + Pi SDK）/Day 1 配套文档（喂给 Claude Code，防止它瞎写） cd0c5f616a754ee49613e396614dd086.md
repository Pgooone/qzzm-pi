```
## defineTool 标准模板
```

const writePrd = defineTool({

name: "write_prd",

label: "写入 PRD",

description: "...",

parameters: Type.Object({

content: Type.String({ description: "完整 PRD markdown" }),

version: Type.String(),

}, { additionalProperties: false }),  // ← DeepSeek 严格模式建议加

execute: async (toolCallId, params, signal, onUpdate) => {

// 可选：onUpdate({ type: "text", text: "30% 完成..." }) 推流式进度

// signal.aborted 可用于响应取消

return {

content: [{ type: "text", text: "OK" }],   // ← 必须是数组

details: { path: "/abs/path", size: 1234 }, // 可放任意元数据

}

},

})

```
**返回必须是 `{ content: ToolResultContent[], details? }`，不要返回 string。**

`ToolResultContent` 有 `text | image | audio | resource | resource_link` 五种，PRD/代码场景几乎只用 `text`。
```

## 五、docs/[pi-integration-architecture.md](http://pi-integration-architecture.md)

```markdown
# Pi 多 Agent 嵌入架构（参考 openclaw）

## 核心思想（必须遵守）
- **一个 Pi session = 一个 Agent**，不是一个 session 演 4 个角色
- 不同 Agent 间**不共享对话历史**；只通过文件级 artifacts 移交
- Pi session 全部在 gateway 进程内创建，前端只通过 WS 收事件

## 项目实现
```

state/

projects/

<projectId>/

sessions/

prd.jsonl       # 需求 Agent 历史

design.jsonl    # 设计 Agent 历史

dev.jsonl

review.jsonl

artifacts/

[prd.md](http://prd.md)          # 最新版

[prd.md](http://prd.md).v1       # 历史版本

[prd.md](http://prd.md).v2

[design.md](http://design.md)

ui/*.html

workspace/        # 开发 Agent 的代码工作区

...生成的项目代码...

```

## 跨 Agent 移交契约
- 一律通过 `artifacts/` 文件传递，不在 LLM 上下文里塞另一个 Agent 的对话
- 切 Tab 时：前端 `useAgentSocket` 发 `{ kind: "switch_role" }`，gateway 创建/激活该 role 的 session
- 一个 projectId → 一个目录，N=4 个角色 session 互不污染上下文

## openclaw 借鉴的设计点
- **session-per-agent**：避免单 session 上下文爆炸
- **handoff via artifacts**：传文件而不是传对话
- **resource loader override**：用代码注入 4 套不同 system prompt，而不是在 user message 前缀拼

## 我们没采用的（Day 1 简化）
- openclaw 多容器隔离 — Day 1 单进程足够
- openclaw 的协议总线 — 我们用 Node EventEmitter + WS 推
- 沙箱执行 — Day 1 不开（开发 Agent 起来后再考虑 docker exec）

参考：https://docs.openclaw.ai/pi#pi-integration-architecture
```

## 七、docs/[ws-protocol.md](http://ws-protocol.md)

```markdown
# WS 协议（前后端唯一桥）

路径：`ws://localhost:8787/ws/:projectId`
单连接绑定一个 projectId，gateway 自动管理底层 N 个 Pi session（按 role 切）。

## 客户端 → 服务端 (InMsg)
```

{ kind: "prompt",      text: string, behavior?: "steer"|"followUp" }

{ kind: "abort" }

{ kind: "compact",     instructions?: string }

{ kind: "switch_role", role: "prd"|"design"|"dev"|"review" }

```

## 服务端 → 客户端 (OutMsg)
```

{ kind: "hello",            projectId, role }

{ kind: "message_start",    messageId }

{ kind: "text_delta",       messageId, delta }

{ kind: "thinking_delta",   messageId, delta }

{ kind: "message_end",      messageId }

{ kind: "tool_start",       toolCallId, name, params }

{ kind: "tool_update",      toolCallId, chunk }

{ kind: "tool_end",         toolCallId, isError, result }

{ kind: "turn_end" }

{ kind: "agent_end" }

{ kind: "artifact_updated", artifact: { name, version, size, kind } }

{ kind: "error",            message }

```

## 加新事件 SOP
1. `apps/gateway/src/ws.ts` 的 `OutMsg` 或 `InMsg` 联合类型加分支
2. 出站事件：在 `session.subscribe` 的 switch 里 `send({ kind: "...", ... })`
3. `apps/web/src/hooks/useAgentSocket.ts` 加 onmessage case 并 setMessages
4. `apps/web/src/lib/types.ts` 同步 `Msg` 联合类型
5. 在 `MessageList.tsx` 加渲染分支（如果需要在消息流可见）

## ❌ 不要做
- 不要在 WS 里发二进制，全部 JSON.stringify
- 不要在一条 WS 上跑多个 projectId — 一个 ws connection = 一个 project
- 不要在 ws.ts 里写业务逻辑 — 它只做事件转发
```

## 八、docs/[conventions.md](http://conventions.md)

```markdown
# 代码约定

## TypeScript
- `strict: true`，不用 `any`（必要时 `unknown` + 类型守卫）
- 用 ESM (`"type": "module"`)，import 路径加 `.js` 后缀（`./foo.js`）以兼容 Node 原生 ESM
- 函数组件 + Hook，不写 class component
- 异步统一 `async/await`，少用裸 `.then()`

## 命名
- 文件：camelCase 或 kebab-case；组件 PascalCase（与文件同名）
- WS 消息 kind：snake_case
- artifacts 文件名：小写 `prd.md` / `design.md` / `review.md`
- 函数：动词开头 `buildXxx` / `createXxx` / `loadXxx`
```
