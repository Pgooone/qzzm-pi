> **项目名称**：全栈智码（Full-Stack Smart Code）  
> **PRD 版本**：v1（草稿）  
> **编写日期**：2026-05-08  
> **编写者**：需求 Agent

## 1. 项目背景与目标

### 1.1 背景

当前软件研发流程中，需求分析、系统设计、代码开发、代码审查等环节通常由不同角色人工完成，环节之间信息传递断裂、效率低下、质量参差不齐。随着大语言模型（LLM）能力的快速提升，AI Agent 已经能够独立承担部分研发环节的工作。

Pi Coding Agent（[https://pi.dev/docs/latest](https://pi.dev/docs/latest)）是一个终端化的编码 Agent 框架，提供了 SDK、RPC 模式以及丰富的扩展机制（详见 [https://docs.openclaw.ai/pi#pi-integration-architecture](https://docs.openclaw.ai/pi#pi-integration-architecture)），能够被嵌入到上层平台中以驱动代码生成、审查等任务。

**全栈智码**旨在构建一个**多 Agent 驱动**的一体化研发平台，通过 4 个专业化 AI Agent 覆盖需求 → 设计 → 开发 → 审查的全流程，显著提升软件研发的质量与效率。

### 1.2 目标

1. **需求 Agent**：面向产品经理/业务人员，从一句话/资料/想法出发，输出高质量、可导出的 PRD 文档。
2. **设计 Agent**：面向架构师/设计师，基于 PRD 输出概要设计、详细设计、接口设计、数据库设计及 UI 高保真原型。
3. **开发 Agent**：面向开发工程师，基于 PRD 与设计文档输出可编译、可打包部署的完整代码集。
4. **审查 Agent**：面向 QA/架构师，对已开发代码进行审查和测试，输出审查报告与测试报告。
5. **Pi Coding Agent 集成**：将 Pi Coding Agent 作为底层编码引擎，通过 SDK/RPC 模式驱动开发 Agent 和审查 Agent 的核心能力。

### 1.3 核心理念

- **产出物高度可用**：PRD/设计文档支持 Markdown 预览及 DOC/PDF 导出；UI 原型为真正可交互的高保真页面；代码能编译运行并可打包部署；审查/测试报告支持 Markdown、DOC、Excel、PDF 导出。
- **人机协同**：每个环节的产出物均可由用户多次提出修改意见，Agent 迭代修改直至用户定稿。
- **渐进式构建**：先聚焦 4 个核心模块，后续逐步完善细节功能。

## 2. 核心用户与场景

### 2.1 用户角色

| 角色 | 描述 | 使用场景 |
|---|---|---|
| **产品经理** | 负责需求分析与 PRD 编写 | 快速将想法转化为结构化 PRD |
| **架构师/设计师** | 负责系统设计与 UI 设计 | 基于 PRD 快速完成技术设计与 UI 原型 |
| **开发工程师** | 负责前后端代码实现 | 根据设计文档自动生成代码 |
| **测试/质量保障人员** | 负责代码审查与测试 | 审查代码质量并输出测试报告 |
| **项目经理** | 统筹项目进度 | 检查各环节产出物质量，把控里程碑 |

### 2.2 用户故事

#### 场景一：需求定稿

- **As a** 产品经理  
  **I want** 向平台输入一句话需求或上传业务资料  
  **So that** 平台自动生成结构完整的 PRD 文档，减少重复编写工作

- **As a** 产品经理  
  **I want** 对生成的 PRD 进行修改意见反馈  
  **So that** 需求 Agent 能根据反馈迭代修改直至最终定稿

- **As a** 产品经理  
  **I want** 将定稿后的 PRD 导出为 DOC 和 PDF 格式  
  **So that** 可以发送给团队或客户审阅

#### 场景二：设计定稿

- **As a** 架构师  
  **I want** 基于定稿的 PRD 自动生成概要设计和详细设计文档  
  **So that** 减少文档编写时间并保证需求到设计的可追溯性

- **As a** 架构师  
  **I want** 自动生成接口设计文档和数据库设计文档  
  **So that** 前后端团队可以基于接口定义并行开发

- **As a** 设计师  
  **I want** 基于 PRD 和设计文档生成 UI 高保真交互原型  
  **So that** 在开发前可视化最终效果并收集反馈

- **As a** 设计师  
  **I want** 对 UI 原型反复提出修改意见  
  **So that** 设计 Agent 能迭代优化直至最终定稿

#### 场景三：代码开发

- **As a** 开发工程师  
  **I want** 基于定稿的 PRD 和设计文档启动开发 Agent  
  **So that** 自动生成完整可编译运行的前后端代码

- **As a** 开发工程师  
  **I want** 生成的代码包含完整的工程结构和构建配置  
  **So that** 可以直接编译、打包和部署上线

#### 场景四：代码审查与测试

- **As a** 质量保障人员  
  **I want** 对开发完成的代码进行自动审查  
  **So that** 快速发现代码质量问题、安全漏洞和最佳实践偏离

- **As a** 质量保障人员  
  **I want** 自动执行测试并生成测试报告  
  **So that** 评估代码的功能正确性和覆盖率

- **As a** 质量保障人员  
  **I want** 将审查报告和测试报告导出为 Markdown、DOC、Excel、PDF 格式  
  **So that** 可以归档或分发给相关方

## 6. 技术架构概要

### 6.1 整体架构

```
┌─────────────────────────────────────────────────────────┐
│                    全栈智码 Web 前端                         │
│  (需求定稿 | 设计定稿 | 代码开发 | 代码审查 四个工作台)         │
└────────────────────────┬────────────────────────────────┘
                         │ HTTP/WebSocket
┌────────────────────────▼────────────────────────────────┐
│                   平台后端服务 (Node.js)                     │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐   │
│  │需求Agent │ │设计Agent │ │开发Agent │ │审查Agent │   │
│  │(LLM编排) │ │(LLM编排) │ │(Pi SDK)  │ │(Pi SDK)  │   │
│  └──────────┘ └──────────┘ └────┬─────┘ └────┬─────┘   │
│                                  │             │          │
│  ┌───────────────────────────────▼─────────────▼──────┐  │
│  │           Pi Coding Agent SDK (嵌入式集成)            │  │
│  │  createAgentSession | ModelRegistry | AuthStorage   │  │
│  │  SessionManager | 自定义 Tool 注入                    │  │
│  └───────────────────────┬────────────────────────────┘  │
└──────────────────────────┼──────────────────────────────┘
                           │
              ┌────────────┴────────────┐
              │    LLM 模型 (API 调用)     │
              │ Claude / GPT / Gemini   │
              └─────────────────────────┘
```

### 6.2 Pi Coding Agent 集成设计

参照 [Pi 集成架构](https://docs.openclaw.ai/pi#pi-integration-architecture) 的最佳实践：

1. **嵌入式集成**：使用 Pi SDK 的 `createAgentSession()` 直接在平台后端进程中创建 Agent 会话，而非作为子进程调用（RPC 模式）。
2. **自定义工具注入**：
   - 为开发 Agent 注入文件读写、包管理（npm/pip）、代码编译等工具
   - 为审查 Agent 注入静态分析、测试框架执行等工具
3. **会话管理**：利用 Pi 的 `SessionManager` 实现项目级别的会话持久化，支持分支和回溯。
4. **事件订阅**：通过 `session.subscribe()` 实时获取 Agent 的流式输出、工具执行状态等事件，推送到前端展示。
5. **模型切换**：通过 Pi 的 `ModelRegistry` 支持多模型切换和 failover。

### 6.3 技术选型建议

| 层级 | 技术选型 |
|---|---|
| 前端框架 | React / Vue 3 |
| 后端运行时 | Node.js (TypeScript) |
| Pi SDK | `@earendil-works/pi-coding-agent` |
| Pi AI | `@earendil-works/pi-ai` |
| Pi Agent Core | `@earendil-works/pi-agent-core` |
| 数据库 | SQLite（原型阶段）/ PostgreSQL |
| 文件存储 | 本地文件系统 → MinIO/S3 |
| 文档导出 | Pandoc / `markdown-it` + `puppeteer` (PDF) |
| UI 原型工具 | 前端代码直接生成（HTML/CSS/JS） |

| **M3：设计定稿模块** | 第 5-7 周 | 设计定稿模块完整可用 | 包含概要/详细/接口/数据库设计和 UI 原型 |
| **M4：开发 Agent 与审查 Agent** | 第 8-10 周 | 代码开发和审查模块可用 | 基于 Pi SDK 驱动代码生成和审查 |
| **M5：导出与集成测试** | 第 11-12 周 | 全流程打通，所有导出功能可用 | 端到端验证，导出格式验证 |
| **M6：上线发布** | 第 13 周 | v1.0 正式版上线 | |

### 7.2 风险与应对

| 编号 | 风险 | 影响 | 概率 | 应对策略 |
|---|---|---|---|---|
| R01 | Pi SDK API 变动导致集成困难 | 集成工作重复 | 中 | 锁版本号，跟随官方更新策略 |
| R02 | LLM 生成代码质量不稳定 | 代码可用性下降 | 中 | 引入编译验证和单元测试自动检查 |
| R03 | UI 高保真原型交互效果不达预期 | 用户满意度下降 | 中 | 提供现成 UI 组件库约束，确保生成质量 |
| R04 | 大模型 Token 成本过高 | 运营成本超预算 | 高 | 引入 Token 用量监控、缓存机制、模型降级策略 |
| R05 | 生成的 PRD/设计文档结构不完整 | 输出质量不达标 | 中 | 使用 Prompt Engineering + 结构化输出约束 |
